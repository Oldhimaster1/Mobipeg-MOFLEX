Real encoding.
Clear expectations.

MobiPEG Web Studio runs the modified V15 FFmpeg/x264 MobiClip encoder locally through WebAssembly. Your video is never sent to a conversion server. The site downloads its own code and engine; selected media stays on your device.

Getting started

  1. Select a video and preview it. Browser preview support and encoder input support can differ.
  2. Choose 2D, full-SBS or half-SBS to match the source. SBS conversion preserves existing stereo; it does not invent depth from 2D.
  3. Choose resolution, frame rate and quality. Start with a short clip to measure this device.
  4. Keep this page visible until encoding and verification finish, then download your MOFLEX.

Queue & storage estimate

Select several videos to build a local conversion queue. Each item keeps its own settings and can be selected, reordered or removed before starting. Videos encode one at a time. After each verified result, start its download and then continue; this releases that result before the next encode. Reloading the page clears the queue.

The displayed output range and peak temporary-storage requirement are planning estimates, not guarantees. Source motion, detail, audio and advanced settings can change the final size. Available browser storage is shown when the browser provides it; your normal downloads folder is separate.

Output preview & framing

Choose a timestamp under Output preview and select Generate preview. The browser renders a framed source image, encodes one MobiClip frame (one pair of coded eyes for stereo), then decodes it for comparison. Choose Left or Right to inspect each eye. This is a video-only I-frame sample, so it does not demonstrate motion prediction, temporal filtering over time, complete-file integrity, or hardware playback. It uses the selected profile quantizer; size-limited conversions may select another value. Preview samples do not increment conversion statistics.

Framing & crop offers Fit (letterbox), Fill (center crop), and Stretch. Manual margins use even source-pixel counts and are applied to each eye after splitting SBS, before aspect correction and scaling. All margins must leave a nonempty picture; incompatible input crops fail without producing an output. Changes invalidate the preview. Reset framing clears margins and restores Fit.

Resolution options range from 256×144 to 800×480 per eye, with 10–60 fps and fractional NTSC rates. Existing defaults are unchanged. Resolutions above 400×240 and display rates above 30 fps are experimental for physical 3DS playback; higher settings increase runtime, memory and output size.

Speed, crop ratios & interface languages

Letterbox / Fit keeps the whole cropped picture and adds borders; Fill center-crops to cover the output frame. Crop aspect ratio adds 4:3, 16:9, 16:10, 5:3, 21:9, square and portrait presets. These are applied after manual margins, separately to each eye, accounting for pixel aspect ratio. Fit or Fill then places that picture into the selected output resolution.

Encoding speed defaults to Original. Fast uses less subpel motion search at the same quantizer; output pixels and file sizes can change. Advanced subme values override this switch. Full video/audio verification remains enabled. Long-movie chapters also reuse the initial input inspection instead of repeating it every chapter. See the small-fixture benchmark for measurements and limitations; these are not full-movie or iPhone speed guarantees.

The header language selector offers English, Spanish, French, German, Portuguese, Japanese, Korean and Simplified Chinese. It follows a supported browser language initially and remembers your selection locally. Interface translations are bundled with the site and do not contact a translation service. Audio, technical diagnostics and this guide retain their original language. Filenames and encoder settings are never translated.

Advanced parameters

Open Advanced and enable Parameter overrides for direct V15 controls: -me_method, -g, MOBI_SUBME, skip and motion-refinement thresholds, scaler flags and input range, hqdn3d coefficients, and audio gain/highpass/lowpass filters. Blank fields inherit the current profile. The invocation preview shows the generated arguments and environment; these are not an arbitrary FFmpeg shell. Stereo mapping, pixel format, output codec and movie audio alignment remain managed by MobiPEG.

Custom hqdn3d coefficients replace Image treatment. Subme 1 is rejected because it desynchronizes the custom codec. Expensive search settings can substantially increase encoding time. Turning Parameter overrides off ignores its values; Reset clears them. The conversion report includes active overrides. These settings have software decode checks, not physical 3DS certification.

Stereo & sound

Layout 0 encodes left then right, separately, at twice the displayed frame rate. At 24 stereo pairs per second, there are 48 coded eye frames per second. Half-SBS aspect correction is applied before each eye is scaled. Audio is converted to stereo 44.1 kHz ADPCM, padded or trimmed to the encoded video duration.

Browser limitations

This is a release preview, not a certified production release. The FFmpeg scheduler uses WebAssembly threads; the codec uses one thread for reproducibility. The host must enable cross-origin isolation with COOP/COEP response headers. WASM can be slower than native. Automatic mode selects the SIMD-optimized codec when supported; Compatibility uses the scalar build. The current muxer buffers media in memory. Long movies and high-resolution inputs may exhaust available browser memory. A successful desktop encode does not establish an iPhone memory limit. Safari on a physical iPhone and actual Old3DS/New3DS playback require separate testing.

Keep the screen on and the tab visible. A screen wake lock is requested when available, but mobile operating systems can still suspend or terminate tabs. Cancel ends the worker immediately; there is no pause/resume or recovery after a refresh. Progress and remaining time are estimates for the current stage, not the entire multi-trial job.

Verification

The app decodes all output video and audio before offering the download and checks coded frame counts. This does not certify the Nintendo player's seeking, stereo presentation, or hardware playback. Full test results, source, build instructions and engine provenance are included with the project download.

Privacy & usage statistics

Privacy: videos and filenames stay on your device. Unless you opt out, we send Cloudflare a page-view count and, after a verified conversion, its duration and input/output sizes. Only daily totals are stored; no cookies or visitor IDs. Cloudflare processes connection metadata, including your IP address. Browser Do Not Track and Global Privacy Control signals are respected.

Statistics describe page views, verified conversions, converted duration and file sizes. They do not identify unique people. Use the checkbox at the bottom of the studio to opt out. This preference is stored locally; interface-language preferences are also stored locally. Neither setting is a visitor identifier.
